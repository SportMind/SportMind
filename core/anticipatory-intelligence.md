# Anticipatory Intelligence

**How to prepare reasoning frameworks before signals occur.**
Pre-built scenario maps are more reliable than reactive reasoning under time pressure.

---

## 30-day event horizon

```
SCHEDULED EVENTS THAT ALWAYS REQUIRE ANTICIPATORY PREPARATION:
  · Match fixtures (all competitions)
  · Transfer window open/close dates
  · Regulatory decision dates (where publicly known)
  · Fan token governance vote windows
  · FTP PATH_2 pre-liquidation windows ($AFC)
  · Major tournament draws and stage progressions
  · UCL/World Cup knockout rounds
  · Contract expiry dates for key commercial partnerships

PREPARATION TIMELINE:
  30+ days: identify event, note in calendar
  14 days:  begin scenario map construction
  7 days:   complete scenario map, set monitoring triggers
  48h:      update scenario map with any new signals
  T-2h:     switch from anticipatory to confirmed signal reasoning
```

## Pre-match anticipatory framework

```
UCL FINAL EXAMPLE (reference timeline):
  14 days before: load both clubs' full athlete intelligence
  7 days before:  scenario map complete — all 3-4 scenarios built
  48h before:     press conference signals integrated
  24h before:     injury news and form signals updated
  T-6h:           lineup scenario split confirmed/unconfirmed
  T-2h:           confirmed lineup → execution quality signal

  This 14-day preparation produces materially better signals than
  a 2-hour reactive analysis because:
  · Historical patterns already loaded
  · Scenario modifiers already calculated
  · Only final confirmation data needed at T-2h
```

## Anticipatory demand modifiers

```
HIGH PROBABILITY POSITIVE EVENT APPROACHING (within 5-10 days):
  Apply: ×1.05 demand premium building
  Examples: UCL final participation confirmed, title mathematically possible,
    major new partnership announcement expected, World Cup qualification

HIGH PROBABILITY NEGATIVE EVENT APPROACHING (within 5-10 days):
  Apply: ×0.95 demand discount building
  Examples: relegation mathematically likely, governance vote on supply changes,
    regulatory decision expected unfavourable

ANTICIPATED EVENT CONDITIONS:
  "High probability" = above 70% likelihood based on available intelligence.
  Apply modifier from 5-10 days before, not sooner.
  Earlier application reduces signal quality — market noise too high.
  Modifier fades immediately when event resolves.
```

## REASONING CHAIN — ANTICIPATORY SIGNAL PREPARATION

```
STEP 1 — Identify upcoming certain events (within 30 days):
  Scan calendar: matches, windows, regulatory milestones, on-chain events.
  List all events that will produce signals SportMind must reason about.

STEP 2 — Build scenario maps now (not after):
  For each identified event load core/scenario-intelligence.md.
  Build the scenario map before the event.
  Pre-built maps are more reliable than reactive reasoning.

STEP 3 — Identify what would change each scenario:
  What new information between now and the event would shift probabilities?
  Lineup news? Transfer? Regulatory development? Macro shift?
  Document these information triggers explicitly.

STEP 4 — Set monitoring triggers:
  What signals should be watched for between now and the event?
  Document each trigger and which scenario it would confirm.

STEP 5 — Apply anticipatory modifier:
  High probability positive event (5-10 days): ×1.05 demand premium building
  High probability negative event (5-10 days): ×0.95 demand discount building
  Condition: above 70% probability required before applying.

STEP 6 — Execute when event occurs:
  Switch from anticipatory to confirmed signal reasoning.
  Apply the pre-built scenario map.
  Update with confirmed outcome.
  Discard unused scenarios — clean the scenario map.

Cross-reference:
  core/scenario-intelligence.md
  core/temporal-reasoning.md
  core/signal-confidence-framework.md
```
